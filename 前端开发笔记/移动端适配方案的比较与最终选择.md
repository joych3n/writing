# 移动端适配方案的比较与最终选择

对移动端适配方案的调研与最终选择，包含背景、原理、权衡以及 unocss 转换规则示例与注意事项。

## 背景与目标

背景是在同时存在 PC 与移动端的项目中，并且使用 unocss 原子化写法。目标是：

- 开发体验好：按设计稿尺寸直接书写，直观易懂。
- 维护成本低：样式易读、易修改、可渐进迁移。
- 还原度高：像素级或接近像素级还原设计稿。
- 渐进迁移，兼容现有老代码（比如之前不严谨的 rem 写法）。
- 不能破坏继承的字体大小等样式。

## 相关前置知识（补充）

### rem 适配原理

根据屏幕宽度动态设置 html 的 font-size（通常按设计宽度分成若干份）实现适配，1rem = html font-size。优点：字体、间距等基于 rem 的样式都会跟随缩放；缺点：会影响继承的字体大小、与现有 UI 框架的兼容性，以及 PC/移动需区分的复杂性。

### vw 适配原理

vw 是视口宽度的百分比，1vw = 视口宽度的 1%。直接按设计稿 px 换算成 vw，可实现更直观的按宽度适配，不修改根元素 font-size，不影响继承字体大小。

## 被否掉的方案及原因

1、postcss px->rem/vw 插件：适合独立 H5 项目，需加额外标记以排除 PC 样式，适配成本较高但自动化强。（适合独立 H5 项目的最佳实践）

2、媒体查询写法：首先需要添加专属于移动端的类名，其次原子化和样式混合写一起，不优雅（适合非 css 原子化的项目）。

3、口算 vw 直接手写：缺点是效率低，难以像素级还原设计稿（适合没有 UI 图的项目）

4、rem（以根元素 font-size 动态调整）：兼容性好但会影响继承字体，且与现有 PC 并存时需要严格的排除逻辑和边界情况考量。

## 最终方案概述

基于项目特性（PC + 移动并存、unocss 原子化、需兼容老 rem 写法等），选择在 unocss 中设计一套直接写设计稿尺寸、自动转换为 vw 的规则，简单明了，优点包括：

- 直接写设计稿尺寸，直观易懂；
- 不修改根 font-size，不破坏继承字体样式；
- 易于与 unocss 原子化体系集成，开发维护便利，渐进替换。

## unocss 转换规则示例

```js
const DESIGN_WIDTH = 375;

function toVw(n) {
  return `${(Number(n) / DESIGN_WIDTH) * 100}vw`;
}

rules: [
  // 宽度与高度，w-d150 -> width: 40vw
  [/^w-d(\d+)$/, ([, d]) => ({ width: toVw(d) })],
  [/^h-d(\d+)$/, ([, d]) => ({ height: toVw(d) })],

  // 内外边距（上下左右、单边可扩展）
  [/^p-d(\d+)$/, ([, d]) => ({ padding: toVw(d) })],
  [/^px-d(\d+)$/, ([, d]) => ({ paddingLeft: toVw(d), paddingRight: toVw(d) })],
  [/^py-d(\d+)$/, ([, d]) => ({ paddingTop: toVw(d), paddingBottom: toVw(d) })],
  [/^pt-d(\d+)$/, ([, d]) => ({ paddingTop: toVw(d) })],
  [/^pr-d(\d+)$/, ([, d]) => ({ paddingRight: toVw(d) })],
  [/^pb-d(\d+)$/, ([, d]) => ({ paddingBottom: toVw(d) })],
  [/^pl-d(\d+)$/, ([, d]) => ({ paddingLeft: toVw(d) })],
  [/^m-d(\d+)$/, ([, d]) => ({ margin: toVw(d) })],
  [/^mx-d(\d+)$/, ([, d]) => ({ marginLeft: toVw(d), marginRight: toVw(d) })],
  [/^my-d(\d+)$/, ([, d]) => ({ marginTop: toVw(d), marginBottom: toVw(d) })],
  [/^mt-d(\d+)$/, ([, d]) => ({ marginTop: toVw(d) })],
  [/^mr-d(\d+)$/, ([, d]) => ({ marginRight: toVw(d) })],
  [/^mb-d(\d+)$/, ([, d]) => ({ marginBottom: toVw(d) })],
  [/^ml-d(\d+)$/, ([, d]) => ({ marginLeft: toVw(d) })],

  // 字体与行高
  [/^text-d(\d+)$/, ([, d]) => ({ fontSize: toVw(d) })],
  [/^leading-d(\d+)$/, ([, d]) => ({ lineHeight: toVw(d) })],

  // 圆角、间距
  [/^rounded-d(\d+)$/, ([, d]) => ({ borderRadius: toVw(d) })],
  [/^gap-d(\d+)$/, ([, d]) => ({ gap: toVw(d) })],
  [/^gap-x-d(\d+)$/, ([, d]) => ({ columnGap: toVw(d) })],
  [/^gap-y-d(\d+)$/, ([, d]) => ({ rowGap: toVw(d) })],
];
```
